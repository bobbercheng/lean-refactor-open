## 3. The run
1. **Pre-flight (no spend):**
   - Selftest 7/7.
   - Offline chain rehearsal passes.
   - Harness tagged (`a100-80-run`).
   - Credit ≥ the run budget below.
2. **Rent:** `provision.sh` with the chosen rental type, then `bootstrap.sh` (SSH within 180 s, nvtop deadline, host check), the 191 GB download (~4 min on a good host) and server start (2–16 min). Then `server_up --bridge` UP, health watchdog with credit guard.
3. **Passes:** `replicate.sh fresh-a100 openai START=4 PASSES=7`, 4 workers, HEAD harness (tagged), effort low, budget forcing on.
   - After every pass: import, assemble the line, accounting line, health check.
4. **Stop rules:**
   - **Success:** assembled ≥ 80.00, then validate all 15 on every toolchain, then release at once.
   - **No-progress stop:** after pass 5, if the line is < 79.0, stop and release. Reassess the strategy instead of buying more passes; the router (item 4) would send the weakest problems to rethink briefs.
   - **Cost stop:** hard cap of the run budget; the chain releases when the cap is near.
5. **Release guard:** release only after the last pass's DONE lines (15/15) and the assemble line exist (lesson 18).
